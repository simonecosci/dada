# dada — Fase 1 (ciclo completo) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Un team può definire progetti e versioni, registrare credenziali e host (anche dietro jump host), creare deployment con membri e ruoli, installare versioni sugli host, generare `docker-compose.yml` / `.env` / `.env.<slug>` / script, deployare via SSH con log live e fare restart. Il tutto è confezionato in un'immagine Docker pubblicata su ghcr.io dalla CI.

**Architecture:**

- **Applicazione**: Laravel 13 + Inertia/Vue 3 (starter kit ufficiale Vue).
- **Codice per dominio** in `app/<Dominio>/`: Catalog, Infrastructure, Ssh, Deployments, Generation, Deploy.
- **Generazione dei file**: pura, cioè input modelli → output stringhe, testabile senza I/O.
- **Operazioni remote**: dietro l'interfaccia `RemoteShell`. Implementazione reale col client OpenSSH (config temporaneo per host, jump host, known_hosts gestito da dada); un fake per i test.
- **Deploy e restart**: job in coda (Horizon/Redis) con lock per deployment. Log persistiti e trasmessi via Reverb.

**Tech Stack:** PHP 8.5, Laravel 13, Pest, Inertia + Vue 3 + TypeScript + Tailwind + shadcn-vue (dallo starter kit), Fortify (auth + 2FA dallo starter kit), PostgreSQL, Redis, Horizon, Reverb + laravel-echo, symfony/yaml, symfony/process, OpenSSH client + sshpass, monaco-editor, Docker (nginx + php-fpm + supervisord), GitHub Actions, ghcr.io.

**Spec:** `docs/superpowers/specs/2026-10-29-dada-design.md`

## Deviazioni dal design (decise in fase di piano)

- **SSH**: client OpenSSH (`ssh` via Symfony Process) invece di phpseclib. phpseclib 3 (verificato sulla 3.0.56) non espone i canali `direct-tcpip`, quindi non supporta jump host. OpenSSH li gestisce con `ProxyJump`.
- **UI**: shadcn-vue invece di PrimeVue, perché è già incluso nello starter kit Vue insieme a login e 2FA.
- **Password e jump host**: un host con credenziale `password` non può fare da jump host. Tutti i salti di una catena devono usare `ssh-key`; solo l'host finale può usare password (via `sshpass`).
- **Nome dello stack**: `stack_name` è usato anche in compose come `name:` top-level (project name), non solo in swarm.
- **Pull delle immagini**: solo in compose. In swarm lo fa `stack deploy --with-registry-auth`.

## Global Constraints

- PHP `^8.5`, Laravel `^13`. Nessun SQL specifico di un database: deve girare su PostgreSQL (default), MySQL/MariaDB e SQLite (test).
- Nessun legame, import o codice da admink-deploy / admink-release.
- Nomi dei file generati: `docker-compose.yml`, `.env`, `.env.<slug>`, `<slug>.sh`, `restart.sh`.
- Interfaccia degli script: `./<slug>.sh start|stop|restart|status [servizio|all]` e `./restart.sh start|stop|restart|status`.
- Permessi dei file sull'host: `600` per `.env*`, `755` per `*.sh`, `644` per il resto.
- Backup pre-deploy in `<path>/.dada/backups/<YYYYmmdd_His>/`.
- Segreti:
    - cifrati a riposo con APP_KEY (cast `encrypted`);
    - mai in chiaro in risposte API, props Inertia, log dei job, broadcast;
    - rivelabili solo dall'endpoint dedicato, che registra la rivelazione.
- Ogni errore di parsing o validazione della generazione blocca, con messaggio chiaro. Nessun fallback silenzioso.
- Massimo un run (deploy/restart) attivo per deployment.
- Chiavi delle variabili: regex `^[A-Za-z_][A-Za-z0-9_]*$`. Slug: `^[a-z0-9][a-z0-9-]*$`.
- Config in `config/dada.php` (vedi Task 1), con questi default:
    - `deploy.min_free_mb=1024`
    - `deploy.backup_retention=10`
    - `deploy.lock_ttl=3600`
    - `ssh.connect_timeout=10`
    - `ssh.command_timeout=1800`
- Immagine: `ghcr.io/simonecosci/dada` (il remote è `github.com/simonecosci/dada`).

```php
interface RemoteShell {
    /** Esegue $command (già completo di cd/sudo) e unisce stdout+stderr; $onOutput riceve chunk di testo. */
    public function exec(string $command, ?callable $onOutput = null, ?string $stdin = null, ?int $timeout = null): ExecResult;
    /** Scrive $contents in $remotePath (via file temporaneo + mv) e applica chmod $mode. */
    public function put(string $remotePath, string $contents, int $mode = 0644): void;
    public function close(): void;
}
interface RemoteShellFactory { public function for(Host $host): RemoteShell; }
final readonly class ExecResult { public function __construct(public int $exitCode, public string $output) {} public function successful(): bool; }
final class RemoteCommandFailed extends RuntimeException { public static function from(string $command, ExecResult $r): self; }
final class HostKeyChanged extends RuntimeException {}
final class HostKeyFingerprint { public static function sha256(string $knownHostsLine): string; } // "SHA256:<base64 senza padding>"
```

**Comportamento di `OpenSshShell`** (non coperto dai soli test unit, quindi lo si dichiara qui):

- **Alla costruzione**: crea `config('dada.ssh.tmp_path')/<uuid>/`. Per ogni host della catena:
    - scrive la chiave privata (`id_h{id}`, chmod 600);
    - scrive `known_hosts` con le righe `host_key` note;
    - scrive `config` via `SshConfigBuilder`.
- **SshConfigBuilder**: per ogni host genera un blocco `Host dada-h{id}` con:
    - `HostName`, `Port`, `User`, `HostKeyAlias dada-h{id}`, `ProxyJump dada-h{jumpId}` (se c'è un jump);
    - `IdentityFile` + `IdentitiesOnly yes` per le chiavi;
    - `PreferredAuthentications password` + `PubkeyAuthentication no` per la password;
    - `UserKnownHostsFile <file>`, `StrictHostKeyChecking accept-new`, `HashKnownHosts no`;
    - `ConnectTimeout <dada.ssh.connect_timeout>`, `ServerAliveInterval 15`;
    - `ControlMaster auto`, `ControlPath <controlDir>/cm-%C`, `ControlPersist 60`.
- **exec**: `ssh -F <config> dada-h{targetId} -- <command>` tramite Symfony Process.
    - Con credenziale password il comando è prefissato da `sshpass -e` con env `SSHPASS`.
    - Le chiavi con passphrase non sono supportate in fase 1: errore di validazione al salvataggio della credenziale. _[scelta del piano]_
- **Dopo ogni exec**: rilegge `known_hosts`. Le righe nuove per un alias il cui host non aveva `host_key` vengono salvate su quell'host (TOFU).
- **Errori di connessione**:
    - exit 255 con stderr che contiene `REMOTE HOST IDENTIFICATION HAS CHANGED` o `Host key verification failed` → `HostKeyChanged("Chiave host cambiata per <name>")`;
    - altri exit 255 → `RemoteCommandFailed` con l'output.
- **put**: `exec("cat > '<p>.dada-tmp' && chmod <mode> '<p>.dada-tmp' && mv '<p>.dada-tmp' '<p>'", stdin: $contents)`, con i path quotati via `escapeshellarg`.
- **close**: `ssh -O exit` e cancellazione ricorsiva della cartella temporanea. Va chiamato in `finally` da chi usa la shell; c'è anche un `__destruct` di sicurezza.

**HostCheckJob** esegue:

- `uname -sr`
- `docker version --format '{{.Server.Version}}'`
- `nproc`
- `awk '/MemTotal/{print int($2/1024)}' /proc/meminfo`
- `df -Pm / | awk 'NR==2{print $4}'`

e salva `facts = {os, docker, cpus, memory_mb, disk_free_mb}`. Su eccezione: `reachable=false` e `facts.error=<messaggio>`.

`resetKey` azzera `host_key`.

    - `status`: `docker compose ps $SERVICES`.

    - `start` = `docker service scale <full>=<N>`;
    - `stop` = `docker service scale <full>=0`;
    - `restart` = `docker service update --force <full>`;
    - `status` = `docker service ps <full>`.
- **swarm `restart.sh ACTION`**:
    - all'inizio `set -a; . ./.env; set +a`;
    - `start`/`restart`:
        - per ogni init di ogni installazione in `order` lancia `docker run --rm`. Le opzioni del comando sono:
            - `--network <stack>_<rete>` per ogni rete dell'init, oppure `<stack>_default`;
            - `--env-file .env.<slug>`, se presente;
            - `-e K=V` dall'`environment` (mappa o lista);
            - `-v <stack>_<vol>:<path>` per i volumi nominati, `-v` così com'è per i bind;
            - poi l'immagine e il `command` (stringa → così com'è; lista → argomenti quotati).
        - Le altre chiavi dell'init vanno in `BuiltCompose::warnings`, con il messaggio `init <n>: chiave <k> ignorata in swarm`.
        - Poi `docker stack deploy -c docker-compose.yml --with-registry-auth --prune <stack>`.
    - `stop`: `docker stack rm <stack>`.
    - `status`: `docker stack services <stack>`.

            - crea un `DeployRunHost` in `running`;
            - esegue la pipeline in try/catch: su eccezione → host `failed` con messaggio, `$log->error()` e **si continua** con gli host successivi;
        - run `succeeded` se tutti gli host sono riusciti, altrimenti `failed`;
        - `DeployRunUpdated` a ogni cambio di stato;
        - lock rilasciato in `finally`.
        - `failed(Throwable $e)`: run `failed` (con gli host `running` → `failed`) e `Cache::lock(...)->forceRelease()`.
    - `POST /deployments/{d}/deploy`, payload `{deployment_host_id?, pull=true, restart=true, confirm_removals=false}`. Policy `operate`.
        - 409 JSON `{message:'Esecuzione già in corso'}` se c'è un run `active`.
        - 422 JSON `{removals: [...]}` se un host coinvolto ha rimozioni e `!confirm_removals`.
        - Altrimenti crea il `DeployRun` (`queued`), dispatcha il job e risponde con redirect a `/runs/{id}`.
    - Il masker del job viene costruito come `SecretMasker` dei `secretValues` di tutti gli host coinvolti, più i secret dei registry.
