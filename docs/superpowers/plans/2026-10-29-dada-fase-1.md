# dada — Phase 1 (complete cycle) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A team can define projects and versions, register credentials and hosts (even behind a jump host), create deployments with members and roles, install versions on hosts, generate `docker-compose.yml` / `.env` / `.env.<slug>` / scripts, deploy via SSH with a live log and restart. All of it is packaged in a Docker image published to ghcr.io by CI.

**Architecture:**

- **Application**: Laravel 13 + Inertia/Vue 3 (official Vue starter kit).
- **Code per domain** in `app/<Domain>/`: Catalog, Infrastructure, Ssh, Deployments, Generation, Deploy.
- **File generation**: pure, i.e. input models → output strings, testable without I/O.
- **Remote operations**: behind the `RemoteShell` interface. Real implementation with the OpenSSH client (temporary config per host, jump host, known_hosts managed by dada); a fake for tests.
- **Deploy and restart**: queued jobs (Horizon/Redis) with a lock per deployment. Logs are persisted and streamed via Reverb.

**Tech Stack:** PHP 8.5, Laravel 13, Pest, Inertia + Vue 3 + TypeScript + Tailwind + shadcn-vue (from the starter kit), Fortify (auth + 2FA from the starter kit), PostgreSQL, Redis, Horizon, Reverb + laravel-echo, symfony/yaml, symfony/process, OpenSSH client + sshpass, monaco-editor, Docker (nginx + php-fpm + supervisord), GitHub Actions, ghcr.io.

**Spec:** `docs/superpowers/specs/2026-10-29-dada-design.md`

## Deviations from the design (decided at plan time)

- **SSH**: OpenSSH client (`ssh` via Symfony Process) instead of phpseclib. phpseclib 3 (verified on 3.0.56) does not expose `direct-tcpip` channels, so it does not support jump hosts. OpenSSH handles them with `ProxyJump`.
- **UI**: shadcn-vue instead of PrimeVue, because it is already included in the Vue starter kit together with login and 2FA.
- **Password and jump hosts**: a host with a `password` credential cannot act as a jump host. All the hops of a chain must use `ssh-key`; only the final host can use a password (via `sshpass`).
- **Stack name**: `stack_name` is also used in compose as the top-level `name:` (project name), not only in swarm.
- **Image pull**: compose only. In swarm `stack deploy --with-registry-auth` does it.

## Global Constraints

- PHP `^8.5`, Laravel `^13`. No database-specific SQL: it must run on PostgreSQL (default), MySQL/MariaDB and SQLite (tests).
- No ties, imports or code from admink-deploy / admink-release.
- Generated file names: `docker-compose.yml`, `.env`, `.env.<slug>`, `<slug>.sh`, `restart.sh`.
- Script interface: `./<slug>.sh start|stop|restart|status [service|all]` and `./restart.sh start|stop|restart|status`.
- File permissions on the host: `600` for `.env*`, `755` for `*.sh`, `644` for the rest.
- Pre-deploy backup in `<path>/.dada/backups/<YYYYmmdd_His>/`.
- Secrets:
    - encrypted at rest with APP_KEY (`encrypted` cast);
    - never in plaintext in API responses, Inertia props, job logs, broadcasts;
    - revealable only through the dedicated endpoint, which records the reveal.
- Every generation parsing or validation error blocks, with a clear message. No silent fallback.
- At most one active run (deploy/restart) per deployment.
- Variable keys: regex `^[A-Za-z_][A-Za-z0-9_]*$`. Slug: `^[a-z0-9][a-z0-9-]*$`.
- Config in `config/dada.php` (see Task 1), with these defaults:
    - `deploy.min_free_mb=1024`
    - `deploy.backup_retention=10`
    - `deploy.lock_ttl=3600`
    - `ssh.connect_timeout=10`
    - `ssh.command_timeout=1800`
- Image: `ghcr.io/simonecosci/dada` (the remote is `github.com/simonecosci/dada`).

## Review Focus

1. **Variable values with `'`, `"`, `$`, spaces, `#`, newline.**
    - Expected: correctly quoted in `.env`, or generation blocked with a message naming the variable and the installation.
    - Test: Task 10, `EnvFileWriterTest`.
2. **A secret that reappears in the remote output** (echo of a command, `docker login` error).
    - Expected: masked as `******` both in the saved logs and in the broadcasts.
    - Test: Task 14, `DeployHostPipelineTest::masks secrets in remote output`.
3. **Worker that dies or times out mid-deploy.**
    - Expected: the run moves to `failed`, the lock is released and the next deploy starts.
    - Test: Task 14, `DeployJobTest::failed() marks run failed and releases lock`.
4. **YAML pasted in the editor and invalid**: broken syntax, tabs, list instead of map, service without `image`.
    - Expected: it is not saved; the error is shown with the parser's message.
    - Test: Task 5, `ComposeFragmentTest`.
5. **Changed host key or unreachable jump host during a multi-host deploy.**
    - Expected: that host ends up `failed` with an explicit message, the other hosts proceed and the overall run is `failed`.
    - Test: Task 14, `DeployJobTest::continues other hosts when one fails`.

```php
interface RemoteShell {
    /** Runs $command (already complete with cd/sudo) and merges stdout+stderr; $onOutput receives text chunks. */
    public function exec(string $command, ?callable $onOutput = null, ?string $stdin = null, ?int $timeout = null): ExecResult;
    /** Writes $contents to $remotePath (via temp file + mv) and applies chmod $mode. */
    public function put(string $remotePath, string $contents, int $mode = 0644): void;
    public function close(): void;
}
interface RemoteShellFactory { public function for(Host $host): RemoteShell; }
final readonly class ExecResult { public function __construct(public int $exitCode, public string $output) {} public function successful(): bool; }
final class RemoteCommandFailed extends RuntimeException { public static function from(string $command, ExecResult $r): self; }
final class HostKeyChanged extends RuntimeException {}
final class HostKeyFingerprint { public static function sha256(string $knownHostsLine): string; } // "SHA256:<base64 without padding>"
```

**Behavior of `OpenSshShell`** (not covered by unit tests alone, hence declared here):

- **On construction**: creates `config('dada.ssh.tmp_path')/<uuid>/`. For each host in the chain:
    - writes the private key (`id_h{id}`, chmod 600);
    - writes `known_hosts` with the known `host_key` lines;
    - writes `config` via `SshConfigBuilder`.
- **SshConfigBuilder**: for each host it generates a `Host dada-h{id}` block with:
    - `HostName`, `Port`, `User`, `HostKeyAlias dada-h{id}`, `ProxyJump dada-h{jumpId}` (if there is a jump);
    - `IdentityFile` + `IdentitiesOnly yes` for keys;
    - `PreferredAuthentications password` + `PubkeyAuthentication no` for passwords;
    - `UserKnownHostsFile <file>`, `StrictHostKeyChecking accept-new`, `HashKnownHosts no`;
    - `ConnectTimeout <dada.ssh.connect_timeout>`, `ServerAliveInterval 15`;
    - `ControlMaster auto`, `ControlPath <controlDir>/cm-%C`, `ControlPersist 60`.
- **exec**: `ssh -F <config> dada-h{targetId} -- <command>` via Symfony Process.
    - With a password credential the command is prefixed by `sshpass -e` with env `SSHPASS`.
    - Keys with a passphrase are not supported in phase 1: validation error when saving the credential. _[plan's call]_
- **After each exec**: re-reads `known_hosts`. New lines for an alias whose host had no `host_key` are saved on that host (TOFU).
- **Connection errors**:
    - exit 255 with stderr containing `REMOTE HOST IDENTIFICATION HAS CHANGED` or `Host key verification failed` → `HostKeyChanged("Host key changed for <name>")`;
    - other exit 255 → `RemoteCommandFailed` with the output.
- **put**: `exec("cat > '<p>.dada-tmp' && chmod <mode> '<p>.dada-tmp' && mv '<p>.dada-tmp' '<p>'", stdin: $contents)`, with paths quoted via `escapeshellarg`.
- **close**: `ssh -O exit` and recursive deletion of the temporary folder. It must be called in `finally` by whoever uses the shell; there is also a safety `__destruct`.

**HostCheckJob** runs:

- `uname -sr`
- `docker version --format '{{.Server.Version}}'`
- `nproc`
- `awk '/MemTotal/{print int($2/1024)}' /proc/meminfo`
- `df -Pm / | awk 'NR==2{print $4}'`

and saves `facts = {os, docker, cpus, memory_mb, disk_free_mb}`. On exception: `reachable=false` and `facts.error=<message>`.

`resetKey` clears `host_key`.

**Script behavior** (spec §4, with the swarm topology "every host is a manager"):

- **compose `<slug>.sh ACTION [SVC|all]`** (default `all`):
    - `SERVICES` = the installation's non-init services, or `SVC`, which must belong to the installation: otherwise exit 2 with a message.
    - `start`:
        - if `all`, for each init `docker compose --profile init run --rm <init>`; an exit ≠ 0 aborts;
        - then `docker compose up -d $SERVICES`.
    - `stop`: `docker compose stop -t 10 $SERVICES && docker compose rm -f $SERVICES`.
    - `restart`: stop then start.
    - `status`: `docker compose ps $SERVICES`.
- **compose `restart.sh ACTION`**: `start`/`restart`/`status` call `./<slug>.sh ACTION all` for each installation in `order`; `stop` does it in reverse order. `restart` = all the stops (in reverse order), then all the starts.
- **swarm `<slug>.sh ACTION [SVC|all]`** (full name `<stack>_<svc>`; replicas come from `deploy.replicas`, default 1):
    - `start` = `docker service scale <full>=<N>`;
    - `stop` = `docker service scale <full>=0`;
    - `restart` = `docker service update --force <full>`;
    - `status` = `docker service ps <full>`.
- **swarm `restart.sh ACTION`**:
    - at the start `set -a; . ./.env; set +a`;
    - `start`/`restart`:
        - for each init of each installation in `order` it launches `docker run --rm`. The command options are:
            - `--network <stack>_<network>` for each network of the init, or `<stack>_default`;
            - `--env-file .env.<slug>`, if present;
            - `-e K=V` from `environment` (map or list);
            - `-v <stack>_<vol>:<path>` for named volumes, `-v` as is for binds;
            - then the image and the `command` (string → as is; list → quoted arguments).
        - The init's other keys go to `BuiltCompose::warnings`, with the message `init <n>: key <k> ignored in swarm`.
        - Then `docker stack deploy -c docker-compose.yml --with-registry-auth --prune <stack>`.
    - `stop`: `docker stack rm <stack>`.
    - `status`: `docker stack services <stack>`.
